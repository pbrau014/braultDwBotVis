1. PROJECT IDENTITY
===============================================================================
DWBOT is the World of Warships YOLO Tournament Discord bot, local tournament scoring engine, screenshot OCR/image-extraction pipeline, Discord integration and desktop Player/Admin interface.

It combines tournament scoring/state with 50 players, four events and seven game slots per player/event; Discord commands and image attachments; strict OCR validation; and desktop Player/Admin/upload pages using the same bot state and OCR queue. plan1.txt remains the full append-only roadmap and historical change record.

4. CURRENT ARCHITECTURE
===============================================================================
Tournament:
src/tournament.js is authoritative scoring/state, 50-player capacity, four events, seven games, JSON and optional built-in SQLite.
playerAccountLinks maps unique Discord snowflakes to roster player IDs.

Discord:
src/bot.js owns Discord lifecycle, command routing, attachments and shared OCR entry point.
src/discord-gateway-diagnostics.js checks target-channel type and effective View/Send/Attach permissions.
Discord.js owns heartbeat/reconnect/resume. Message Content intent is required for existing prefix and attachment visibility. No GuildMembers or Presence intent.
src/tournament-command-policy.js makes setting/settings admin-only.
scripts/preflight-discord-test.js is offline validation only.
Keep ENABLE_SLASH_COMMANDS=0 until an isolated guild test.

OCR:
Tesseract.js remains the baseline. extractText(imageBuffer) uses the bounded serial queue and supervised OCR worker. Image localization and OpenCV geometry isolate evidence only. PaddleOCR is optional local secondary candidate. OCR.space is optional localized-crop evidence with quota ledger, disabled by default.
src/ocr-sequence-checkpoint.js + scripts/run-ocr-sequence.js persist atomic per-image progress; this does not claim acceptance or automatic resumability.

Desktop:
desktop/index.html sign-in landing.
desktop/player.html and player.js: Player totals, standings, event scores, owned screenshot submissions and OCR review/mapping.
desktop/admin.html and admin.js: roster, account links, manual scores, scoring settings, review, standings and private backup.
desktop/upload.html and upload.js: one-image file picker/drop/preview/validation/progress.
desktop/desktop.css and desktop.js shared styles and API behavior.
Original workbook and image reader HTML files remain in dwbotStuff as source baselines; the new pages are derivatives.

Bridge/service:
src/desktop-bridge.js: loopback-only Node HTTP server, Discord OAuth identify, nonce/session cookie, CSRF, strict origin/Host, file-size/signature checks, rate limits, CSP, audit.
src/desktop-service.js reuses tournament state/scoring/BattleRecord validators and existing extractText queue.
Players see own records and can map only exact linked identity. Mismatch remains admin-review. Admin operations checked by service, not UI.
Bridge starts only after Discord READY/channel preflight and only with ENABLE_DESKTOP_UI=1. Shutdown closes it. Desktop Admin requires TOURNAMENT_ADMIN_IDS; Manage Server alone is insufficient.

5. PUBLIC AND PRIVATE BACKUP CONTRACT
===============================================================================
Full private local state contains account links, desktop record ownership IDs and per-user pending workflows. Authenticated local Admin GET /api/admin/backup returns full private archive.
Public Discord snapshots and public !yolo export / !yolo finalize use makePublicArchiveSnapshot. They retain scores and battle records but omit player_account_links, desktop_owner_id/desktop_owner_role, pending_submissions and pending_ocr_corrections. Counts and explanatory note are retained.
Public snapshot is not complete private backup. Importing one requires account relinking and restart of omitted pending workflows. Use authenticated local Admin backup for complete private recovery.

6. EXACT OCR CONTRACT
===============================================================================
Nine mandatory fields, exact order:
1 result
2 player
3 map
4 mode
5 battleStart
6 credits
7 freeXp
8 damage
9 xp

XP is mandatory and ninth. Invalid, ambiguous or conflicting required values remain unresolved. No fuzzy player/name/numeric repair, no expected-value injection and no weakening acceptance tests.
Tesseract.js baseline; OpenCV geometry only; PaddleOCR/OCR.space secondary evidence. OCR.space remains disabled by default. No live OCR.space call/image transmission.
Grand Yolo tierWeight 0.9; workbook H12 =0.54*G12/100, default $12.49.
