What happens next?

The screenshot is checked against all nine mandatory fields: result, player, map, mode, battle start, credits, Free XP, damage and XP. No fuzzy value repair is applied. Missing or conflicting values remain unresolved and require exact correction before mapping.

Desktop uploads use the same PDF-first OCR pipeline as Discord attachments. The original screenshot is submitted to OCR.Space Engine 2 to create a searchable PDF. The PDF is validated and downloaded, then rendered locally; Tesseract.js, native Tesseract and other enabled local readers operate only on that PDF-derived raster. If PDF creation, download, validation or rasterization fails, processing stops for that image rather than falling back to OCR on the original screenshot. OCR.Space must be explicitly enabled with OCRSPACE_ENABLED=1 and OCRSPACE_NETWORK_ALLOWLIST=1, with the API key kept in the local bot environment. Provider text is retained as separate evidence and cannot independently accept or overwrite a required field; exact local validation and review remain in force.
